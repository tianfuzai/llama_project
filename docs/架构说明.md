# 架构说明

## 1. 项目流水线总览

本项目完成「**数据蒸馏 → 数据登记 → SFT 微调 → DPO 偏好对齐 → 模型加载 → 效果评估**」六个环节的完整闭环，业务场景为**山西本地政务问答**。

```
┌────────────┐   ┌──────────────┐   ┌──────────────┐   ┌─────────────┐
│ ① 数据蒸馏  │──▶│ ② 数据登记    │──▶│ ③ SFT 微调   │──▶│ ④ DPO 对齐  │
│ 爬虫+分块    │   │ dataset_info │   │ 4组超参实验  │   │ 偏好配对训练 │
│ +QA抽取     │   │ Alpaca/Share │   │ LoRA         │   │ LoRA+DPO    │
└────────────┘   └──────────────┘   └─────────────┘   └─────────────┘
                                             │
                                             ▼
┌────────────┐   ┌──────────────┐
│ ⑥ 效果评估  │◀──│ ⑤ 模型加载    │
│ 50题测试集   │   │ PEFT加载LoRA │
│ 人工+大模型  │   │ 基座vs LoRA  │
│ 三方对比     │   │              │
└────────────┘   └──────────────┘
```

## 2. 各环节说明

| 环节 | 输入 | 关键脚本 | 输出 | 对应需求 |
|---|---|---|---|---|
| ① 数据蒸馏 | 山西政务服务网公开办事指南 | `crawl_shanxi.py` → `clean_and_chunk.py` → `auto_gen_sft.py` | `sft_data.jsonl`(QA对) | FR-A1~A3 |
| ② 数据登记 | QA 原始数据 | `clean_sft_data.py`、`convert_to_sharegpt.py`、`data/dataset_info.json` | `alpaca_zh.json`、`sharegpt_zh.json` | FR-A5、B1~B3 |
| ③ SFT 微调 | Alpaca/ShareGPT 数据 | `run_train.py` + `train_config/sft_exp1~4.yaml` | `saves/sft_expN`(LoRA) | FR-C1~C5 |
| ④ DPO 对齐 | SFT 结果 + 偏好配对数据 | `build_dpo_data.py` + `train_config/dpo.yaml` | `saves/dpo`(LoRA) | FR-D1~D4 |
| ⑤ 模型加载 | 基座 + LoRA 权重 | `infer_peft.py`、`compare_size.py` | 推理回答、体积对比 | FR-E1~E3、C5 |
| ⑥ 效果评估 | 50 题测试集 + 三模型 | `build_testset.py`、`evaluate.py` | 三方对比表、打分结果 | FR-F1~F4 |

## 3. 关键技术选型

- **基座模型**：Qwen/Qwen2.5-1.5B-Instruct（8GB 显存即可 LoRA 微调）
- **训练框架**：LLaMA-Factory（含 WebUI，命令行统一入口 `run_train.py`）
- **微调方法**：LoRA（只训练 A、B 低秩矩阵，`W = W + A×B`）
- **偏好对齐**：DPO（直接偏好优化，无需显式奖励模型）
- **推理路线**：PEFT `PeftModel` 加载 LoRA（Windows 本机完成；vLLM 需 Linux，作为可选说明）

## 4. 数据与算力约束

- 原始资料 ≥30 篇 / 8 万字；QA 数据集各 ≥500 条；偏好配对 ≥200 组；测试集 ≥50 题
- 人工抽检 50 条，与原文一致率 ≥90%
- 显存门槛：1.5B + LoRA 最低 8GB（本项目规格）
