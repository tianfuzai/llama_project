# 四人小组分工详细说明

项目：垂直领域小模型微调与偏好对齐（LoRA + DPO + 数据蒸馏）
业务场景：山西本地政务问答
分工依据：作业模块 A（数据蒸馏）~ G（工程协作），每人承担 1—2 个模块并落实到具体代码。

---

## 成员1 —— 数据工程（模块 A：数据蒸馏 + 模块 B：数据登记）

### 所做的事
1. 抓取山西政务服务网公开办事指南，采集原始政务文本。
2. 对原始文本做清洗与滑动窗口分块，得到可蒸馏的文本块。
3. 设计 QA 抽取提示词，调用本地大模型批量蒸馏出 QA 对。
4. 对蒸馏结果做清洗统计（去重、去空、过滤过长过短、统一标点）。
5. 生成 ShareGPT 多轮对话格式数据集。
6. 人工抽检 50 条并统计一致率。
7. 编写 `data/dataset_info.json`，登记各数据集供 LLaMA-Factory 识别。

### 编写的代码
| 文件 | 用途 |
|---|---|
| `crawl_shanxi.py` | 爬虫：抓取山西政务服务网办事指南原始文本 |
| `clean_and_chunk.py` | 清洗 + 滑动窗口分块（512字 / 重叠64） |
| `auto_gen_sft.py` | 数据蒸馏：调用本地 Ollama `qwen2.5:7b`，每 chunk 三角度生成 3 条 QA，增量续写去重 |
| `build_sft_jsonl.py` | 备用清洗分块实现，输出 QA 的 jsonl |
| `scripts/clean_sft_data.py` | 清洗统计：去重/去空/过滤(<10字或>800字)/统一全半角 → 输出 `alpaca_zh.json` + `clean_report.txt` |
| `scripts/convert_to_sharegpt.py` | Alpaca → ShareGPT messages 格式，输出 `sharegpt_zh.json` |
| `scripts/sample_check.py` | 随机抽 50 条生成人工抽检表 `sample_check_50.csv` |
| `data/dataset_info.json` | 数据集登记（shanxi_sft / shanxi_alpaca / shanxi_sharegpt / shanxi_dpo） |
| `docs/数据说明.md` | 资料清单、提示词模板、清洗规则、抽检说明 |

### 产出物
`alpaca_zh.json`(511条)、`sharegpt_zh.json`(511条)、`clean_report.txt`、`sample_check_50.csv`

### 对应验收项
FR-A1~A5、FR-B1~B3、数据质量清单、人工抽检一致率 ≥90%

---

## 成员2 —— SFT 微调与超参实验（模块 C）

### 所做的事
1. 部署 LLaMA-Factory，下载/确认基座模型，启动 WebUI。
2. 设计并实现 4 组 LoRA 超参对比实验（覆盖 rank、alpha、学习率）。
3. 记录每组 train loss / val loss，分析欠拟合与过拟合。
4. 完成一次显存不足的降级试验。
5. 统计 LoRA 增量权重与基座模型体积对比。
6. 编写训练实验报告。

### 编写的代码
| 文件 | 用途 |
|---|---|
| `train_lora.py` | 训练入口（调用 LLaMA-Factory） |
| `train_lora.yaml` | 7B QLoRA 配置（备用，显存降级路线） |
| `train_lora_clean.yaml` | 1.5B LoRA 主配置（早期成功跑通） |
| `run_train.py` | 统一训练入口：命令行指定任意 yaml 即可跑 SFT / DPO |
| `train_config/sft_exp1.yaml` | 基准组：rank=8, alpha=16, lr=2e-5 |
| `train_config/sft_exp2.yaml` | rank 增大组：rank=16, alpha=32 |
| `train_config/sft_exp3.yaml` | alpha 同比例组：rank=8, alpha=8 |
| `train_config/sft_exp4.yaml` | 学习率增大组：lr=1e-4 |
| `scripts/compare_size.py` | 统计基座模型与各 LoRA 目录体积对比 |
| `docs/训练实验报告.md` | 4 组超参表、参数取值理由、显存降级记录、体积对比 |

### 产出物
`saves/sft_exp1~4`（LoRA 权重）、4 组 loss 曲线、超参对比表、LoRA 体积对比数字

### 对应验收项
FR-C1~C5、训练过程清单、LoRA 体积远小于基座

---

## 成员3 —— DPO 偏好对齐 + 模型加载推理（模块 D + E）

### 所做的事
1. 构造偏好配对数据（chosen 优质回答 / rejected 较差回答）。
2. 在 SFT-LoRA 结果基础上完成 DPO 偏好对齐训练。
3. 记录 DPO loss 曲线。
4. 用 PEFT 的 `PeftModel` 加载 LoRA 完成推理。
5. 对"仅基座"与"基座+LoRA"做直观对比。
6. 编写偏好对齐说明文档，解释 DPO 原理与 KL 散度作用。

### 编写的代码
| 文件 | 用途 |
|---|---|
| `scripts/build_dpo_data.py` | 构造偏好配对数据：以原始 output 为 chosen，程序化劣化生成 rejected → 输出 `dpo_data.json`(200组) |
| `train_config/dpo.yaml` | DPO 训练配置（在 saves/sft_exp1 基础上续训，pref_beta=0.1） |
| `scripts/infer_peft.py` | PEFT 加载 LoRA 推理，同时输出"基座+LoRA"与"仅基座"两个回答做对比 |
| `docs/偏好对齐说明.md` | DPO 数据构造方式、训练配置、DPO 与奖励模型区别、KL 散度作用 |

### 产出物
`dpo_data.json`(200组)、`saves/dpo`（LoRA）、DPO loss 曲线、基座 vs LoRA 对比样例

### 对应验收项
FR-D1~D4、FR-E1/E3、推理与评估清单、DPO 原理正确解释

## 成员4 —— 效果评估 + 工程协作 + 文档整合（模块 F + G）

### 所做的事
1. 构建 50 题独立领域测试集（不取自训练数据，避免泄漏）。
2. 对基座 / SFT-LoRA / DPO 三方模型在测试集上生成回答。
3. 设计人工打分表与大模型打分提示词，汇总三方对比表并给结论。
4. Git 分支管理（main/dev/feature）、PR 评审、.gitignore 配置。
5. 整合 README 与全部文档，编写部署与复现指南。

### 编写的代码
| 文件 | 用途 |
|---|---|
| `scripts/build_testset.py` | 生成 50 题独立测试集 `testset.json`（人工内置，与训练数据无重叠） |
| `scripts/evaluate.py` | 三方模型生成回答 + 输出人工打分表 `evaluation_manual.csv` + 大模型打分提示词 |
| `.gitignore` | 排除 saves/、checkpoint、大体积数据集，保证不入库 |
| `README.md` | 项目说明、环境/安装/命令、目录结构、四人分工、验收自查 |
| `docs/效果评估报告.md` | 三方对比表模板与结论 |
| `docs/部署说明.md` | 环境安装、硬件门槛、训练与推理命令全流程 |
| `docs/复现指南.md` | 从零复现步骤与随机种子说明 |
| `docs/架构说明.md` | 六环节流水线架构图 |

### 产出物
`testset.json`(50题)、三方评估结果、人工打分表、三方对比表、Git 仓库、README

### 对应验收项
FR-F1~F4、FR-G1~G5、工程与文档清单、git log 多人提交、至少 1 个 PR

---

## 协作要点
- 成员2 的 SFT 训练（saves/sft_exp1）是成员3 的 DPO 前置依赖，两者在时间上有先后。
- 成员1 提供的数据集是成员2/3 训练的前提，建议先完成数据链路再开始训练。
- 成员4 的评估依赖成员3 的 DPO 权重，评估脚本在权重就绪后运行。
- 所有训练配置记录随机种子 `42`，保证实验可复现。
