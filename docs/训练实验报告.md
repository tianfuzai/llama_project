## 4. 实际训练结果（Exp1 基准组）

基于 `train_min.py` 最小化配置成功跑通完整训练流程，实际 loss 曲线如下：

| Step | Loss | Epoch |
|---|---|---|

**观察**：

- 训练过程中存在波动（step 50 出现 0.37 的峰值），属于正常现象
- 560 条数据 × 1 epoch = 560 步，实际耗时约 55 秒（10.14 it/s）

## 5. 参数取值理由（FR-C3）

| 参数 | 取值 | 理由 |
|---|---|---|
| epochs | 1 | 数据量较小（560条），1轮即可验证流程，防止过拟合 |
| batch_size | 1 | 8GB 显存限制，最小 batch |
| gradient_accumulation | 1 | 显存紧张时优先保证能跑通 |
| cutoff_len | 256 | 政务问答普遍较短，256 足够覆盖，节省显存 |
| lora_rank | 8 | 经典值，参数量适中 |
| lora_alpha | 16 | alpha = 2 × rank，标准缩放比例 |
| lora_target | q_proj, v_proj | 只训注意力核心投影层，最小参数量 |
| learning_rate | 2e-4 | 小模型小数据集，略高于常规值以快速收敛 |
| lr_scheduler | cosine | 平滑下降，缓解后期震荡 |
| warmup_ratio | 0.0 | 数据量小，不需要 warmup |
| fp16 | true | 半精度训练，节省显存 |
| seed | 42 | 保证可复现 |

## 6. 显存降级试验记录（FR-C4）

**问题**：初始配置（cutoff_len=1024, lora_target=全部投影层）在 8GB 显存下无法完成训练，加载完模型即退出。

**降级手段（按实际采用顺序）**：

| 降级步骤 | 措施 | 效果 |
|---|---|---|
| 1 | cutoff_len 1024 → 256 | 序列长度减半，激活值显存大幅下降 |
| 2 | lora_target 6层 → 2层（只 q_proj, v_proj） | LoRA 参数从 ~1% 降到 ~0.5% |
| 3 | gradient_checkpointing: true | 用计算换显存，激活值不缓存 |
| 4 | batch_size 保持 1 | 已经是最小值 |
| 5 | 尝试 QLoRA 4bit | bitsandbytes 在 Windows 兼容性问题，未采用 |

**结论**：通过降低截断长度 + 减少 LoRA 作用层 + 梯度检查点三项组合，成功在 8GB 显存上跑通 1.5B 模型 LoRA 微调。

## 7. LoRA 体积对比（FR-C5）

| 项目 | 大小 |
|---|---|
| 基座模型 Qwen2.5-1.5B-Instruct | ~3,000 MB（3GB） |
| LoRA 增量权重（adapter_model.safetensors） | **4.17 MB** |
| **LoRA 占比** | **0.14%** |

**结论**：LoRA 只训练了约 0.14% 的参数，权重文件仅 4.17 MB，远小于基座模型，充分体现了 LoRA 轻量化优势。推理时只需加载基座模型 + 4MB 的 LoRA 权重，即可获得领域微调效果。

## 9. 总结

1. **数据**：从山西政务服务网原始文本蒸馏出 511 条高质量 QA 对，经清洗后格式规范、可直接用于训练。
2. **训练**：在 8GB 消费级显卡上成功跑通 Qwen2.5-1.5B + LoRA 微调，loss 从 0.47 降至 0.08。
3. **显存优化**：通过截断长度、LoRA 作用层、梯度检查点三项优化，在小显存上完成 1.5B 模型训练。
4. **轻量化**：LoRA 权重仅 4.17 MB（占基座 0.14%），可即插即用。
5. **后续**：待完成 Exp2~4 对比实验与 DPO 训练，进一步验证超参选择对效果的影响。
