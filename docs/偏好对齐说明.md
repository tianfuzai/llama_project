# 偏好对齐说明

## 1. DPO 数据构造方式（FR-D1 / FR-D2）

运行 `scripts/build_dpo_data.py`：

- **chosen（优质回答）**：采用原始蒸馏得到的 output（基于原文的准确回答）
- **rejected（较差回答）**：程序化"劣化"生成——截断丢失关键信息、加入口语化冗余，确保明显劣于 chosen
- 构造为 ShareGPT messages 格式：

```json
{
  "messages": [{"role": "user", "content": "问题"}],
  "chosen": {"role": "assistant", "content": "优质回答"},
  "rejected": {"role": "assistant", "content": "较差回答"}
}
```

- 数量：≥200 组（当前 200 组达标）
- 数据来源：由 SFT 训练数据的优质回答程序化劣化得到，来源明确可追溯

## 2. DPO 训练配置（FR-D3）

`train_config/dpo.yaml`：

- 在 SFT-LoRA 结果基础上续训（`adapter_name_or_path: ./saves/sft_exp1`）
- `pref_beta: 0.1`、`pref_loss: sigmoid`
- 运行：`python run_train.py train_config/dpo.yaml`
- 输出：`saves/dpo`

DPO 需要同时持有策略模型与参考模型，显存要求高于 SFT；不足时可降低 batch / cutoff 或换更小基座。

## 3. DPO 与显式奖励模型的区别（FR-D4）

- **显式奖励模型（RM）路线**：训练一个单独的奖励模型为回答打分，再用 PPO 等策略梯度优化策略模型。需要训练 RM 并维护奖励信号，训练流程复杂、不稳定。
- **DPO 路线**：直接从偏好数据优化策略，不需要单独训练奖励模型。核心思想是把"奖励函数"隐式地融入策略优化的目标函数中，通过 `log σ(β·(π_chosen − π_rejected))` 最大化选择优质回答的概率，同时受 KL 约束。

## 4. KL 散度作为正则项的作用（FR-D4）

DPO 目标函数中，KL 散度项约束优化后的策略不要偏离参考策略（SFT 模型）过远，作用是：

- **防止奖励放大**：避免模型为了迎合偏好而过度改变，产生退化、重复或无意义输出
- **保持生成质量**：约束策略仍在参考模型附近，保留原有语言能力
- **稳定训练**：正则项使优化目标更平滑，缓解过拟合偏好数据

`pref_beta` 控制 KL 约束强度：越大越约束接近参考策略，越小越鼓励贴合偏好数据。
